## 공통 지적 (3명 이상)
1. 데이터·정답 궤적·평가 지표가 없음 → 6번 구현·평가 슬라이드(v9) 복원 필요
2. "적용 전"이 무엇인지 정의 안 됨 → "지연 무시(도착 즉시 보정)"로 명시
3. 지연·주기 수치가 없음 → 센서 주기 표(IMU 200 Hz / 카메라 20 Hz / 거리 30 Hz)
4. 4번 MSCKF·OpenVINS 문장이 실제 방법과 맞지 않고 이해 불가 → 빼거나 범위 축소
5. EKF·PX4를 한 문장으로 설명

## 제어 교수·대학원생의 기술 지적 (사실 확인 완료)
- PX4 EKF2는 과거로 되돌아가 다시 계산하지 않습니다. 필터를 지연된 시간축(delayed fusion horizon)에서 돌리고 output predictor로 현재를 예측합니다. 본 연구의 "과거 상태 재추정"과는 방식이 다르므로, "PX4도 같은 방식"처럼 들리는 문구를 고쳐야 합니다.
- "초기 위치 기준의 이동량"은 과장입니다. flow와 거리센서로 직접 관측되는 것은 속도와 높이입니다. 수평 위치와 yaw는 적분값이라 drift가 남습니다.
- 참고문헌: Garmin 사용설명서와 VectorNav 자료는 약합니다. Groves(2013) 교과서로 대체하세요.
- 예상 질문 1순위: "어떤 데이터, 무엇을 정답으로?", "PX4가 이미 하는데 기여는?", "상태벡터와 측정모델은?"

## 예상 질문 답변 준비
- **데이터:** INSANE의 실내 구간을 쓰고, OptiTrack 궤적을 정답으로 삼습니다. 카메라 타임스탬프는 실제 촬영 시점이고, 여기에 지연을 인위적으로 주입합니다.
- **기여:** 새 알고리즘이 아니라, 차량 분야의 시간 처리 방법을 이 센서 구성에 구현하고 지연 크기별 효과와 처리시간을 정량 비교하는 것입니다.
- **상태와 측정:** 상태는 위치·속도·자세(+IMU 바이어스)입니다. 측정은 회전 보상한 flow와 거리입니다.
