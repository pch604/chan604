## 1. 문구 원칙 (Moonlight 논문 요약에서 가져온 패턴)
Moonlight 사이트는 이 환경에서 직접 열 수 없었습니다. 그래서 검색 결과에 나온 요약문으로 구성을 확인했습니다.

| 요약문의 순서 | v10 적용 |
|---|---|
| 어떤 조건에서 무엇을 하는가 | 2번 결론: "하향 카메라·IMU·거리센서로 드론의 위치·속도·자세를 추정한다" |
| 기존 방법이 **왜** 실패하는가 (원인까지) | 3번 "기존 융합의 한계": 도착한 값을 그대로 쓰면 이전 시점의 움직임을 현재로 잘못 반영 |
| 구성 요소마다 "무엇을 해서 → 무엇을 얻는가" | 5번: 상태 / 예측 / 보정 / 늦은 측정 처리 |
| 기여를 정직하게 | 4번: "새 필터 제안이 아니라 방식별 정확도와 처리시간을 같은 데이터에서 정량 비교" |
| 데이터·비교 대상·지표 | 6번: INSANE, A/B/C, ATE·RE·처리시간, 가설 |

형식은 보내주신 수정본(7장)을 따랐습니다. 굵은 소제목, • 항목, [번호] 인용, 슬라이드 하단 남색 결론 문장입니다. 수정본에서 빠졌던 구현·평가 슬라이드는 다시 넣었습니다.

## 3. 반영한 지적
- **PX4 EKF2 설명 정정:** "최대 지연만큼 늦은 시점에서 융합하고, 현재 상태는 출력 예측기로 계산"으로 고쳤습니다. 본 연구의 방식(과거 상태 재추정)과 구분됩니다.
- **비교 기준 3가지:** A. 지연 무시, B. 지연 시점 융합(PX4 방식), C. 과거 상태 재추정.
- **가설 명시:** B와 C의 정확도는 비슷하고, C는 현재 상태 지연이 없는 대신 연산이 늘어난다.
- **지연 재현 방법:** 도착 시점을 부여한 뒤 도착 순서대로 재생해 실시간 상황을 만듭니다(오프라인 데이터라는 지적에 대한 답).
- **추정 대상 통일:** "위치·속도·자세"로 맞추고, 수평 위치 오차가 누적된다는 한계를 명시했습니다.
- **보정 문구:** 거리 측정을 두 번 쓰는 것처럼 읽히지 않게 "영상 이동(회전 성분 제거)과 거리(기울기 보정한 고도)"로 고쳤습니다.
- **[6] Qin & Shen 인용 문구:** "카메라와 IMU의 시간이 어긋나면 추정 정확도가 저하"로 논문 내용에 맞췄습니다.
- **ATE:** "위치+yaw 정렬 후"를 명시했습니다.
- **참고문헌:** Garmin 설명서와 VectorNav 자료를 빼고 Groves 교과서로 대체했습니다. 본문에 나온 9편만 남겼습니다.
- **EKF·센서 주기:** EKF는 대본에서 쉬운 말로 풀었고, 센서 주기는 표 없이 본문 한 줄 수치로 넣었습니다.

## 4. 반영하지 않은 것과 이유
- **시간축(타임라인) 그림 추가 제안**(직원·학부생): 이전에 "AI가 만든 도식은 쓰지 말라"고 하셨기 때문에 넣지 않았습니다. 넣는다면 Qin & Shen(2018) Fig. 1의 실제 표현 방식(센서별 샘플링 시점 vs 타임스탬프 두 줄)을 따르는 것이 근거 있는 방법입니다.
- **일정 대안·OOSM 고전 문헌(Bar-Shalom 2002)**: 계획 자체를 바꾸는 일이라 질의응답 대비로 남겼습니다.

## 5. 질의응답 대비 (교수 예상 질문)
1. **"오프라인 데이터인데 지연이 왜 문제인가?"** → 도착 시점을 부여해 도착 순서대로 재생하므로, 필터는 실시간처럼 늦은 측정을 받습니다.
2. **"B와 C는 결과가 같지 않나?"** → 정확도는 비슷할 것으로 예상합니다. 차이는 현재 상태의 지연 여부와 연산량이고, 지연이 변할 때 B는 horizon을 다시 정해야 합니다.
3. **"위치·yaw는 관측되지 않는데?"** → 맞습니다. 그래서 ATE와 함께 구간별 상대 오차(RE)로 지연 효과를 분리해 봅니다.
4. **"광류는 두 프레임 사이 구간의 값인데 측정 시점은?"** → 두 프레임 사이 구간의 중간 시점(또는 뒤 프레임 시점)으로 정하고, 자이로 보상도 같은 구간으로 맞춥니다.
5. **"Kim & Ahn 절차가 각각 무엇에 해당하나?"** → 지연 보상은 도착 시점과 측정 시점을 구분하는 것, 시간 정렬은 버퍼에서 측정 시점의 IMU·상태를 찾는 것, 재추정은 C의 재계산입니다.
